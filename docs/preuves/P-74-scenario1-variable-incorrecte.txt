######## Analyse
- Faits : nginx actif, HTTP 200, page servie = fichier déployé = MESSAGE-INCORRECT-SCENARIO-1 ; le playbook s'est terminé sans erreur.
- Cause confirmée : valeur de site_message incorrecte dans les vars de linux_base.yml (seul fichier modifié, diff ci-dessus).
- Limite du mode --check observée à l'étape D : la simulation annonce le changement de la page (diff -/+) puis l'assertion
  échoue (failed=1), car en simulation la page n'est pas réellement déployée et le contrôle compare la nouvelle valeur à
  l'ancienne page. L'exécution réelle qui suit réussit (failed=0). La simulation ne remplace pas l'exécution ni les contrôles.
- Retour à l'état initial : linux_base.yml identique à la sauvegarde .etat-initial (diff vide), message attendu servi.
